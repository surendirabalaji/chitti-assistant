Part 1: System design

What the system is, how each piece behaves, and how every graded requirement is proven.

Goal and scope

A personal assistant that runs continuously in the cloud, answers through Telegram and the OpenClaw dashboard, reads a test Gmail inbox and Google Calendar, and reaches out on its own with a morning briefing, meeting alerts, and an evening recap. Each message is routed to the right model: simple and private requests to Gemma on the laptop, heavier and tool-based work to ChatGPT, and private requests are held when the laptop is unreachable.

Success criteria

  • The deployed agent completes the four video requests on the correct routes (local, cloud, held, local), and the Cloud Logging output proves each one.
  • Briefing, alert, and recap arrive in Telegram without being asked, from real scheduled jobs.
  • No email is ever sent without a human clicking Approve, and only to allowlisted addresses.
  • 48 hours of continuous operation with hourly evidence, and state that survives a restart.
  • focus-finder is published on ClawHub and installed fresh on the agent from there.

In scope

Skills: email and calendar (gog), web search, weather, focus-finder. Advanced features: morning briefing, end-of-day recap, proactive alerts, email integration. Security measures claimed: container isolation, permission scoping, credential management.

Out of scope for now

Prompt-injection defense as a claimed measure (optional on Nov 17 if time allows), calendar intelligence, personal knowledge base, additional messaging platforms.

Architecture

Everything conversational lives in the cloud container. The laptop only serves Gemma, reachable over the private tailnet. Coloured lines show the three routes.

Routing and failure policy

Rules are checked from the top; the first match wins. Privacy words: confidential, private, personal, sensitive, password, bank, medical, salary, SSN, diagnosis (list kept in config and the README).

#RuleMatches whenLocal upLocal down
1privacy-sensitiveThe user’s message contains a privacy wordlocalheld privacy-local-unavailable
2long-contextSession size estimate above the threshold measured in F4cloudcloud
3tool-taskMentions email, inbox, calendar, meeting, schedule, search, weather, or the turn comes from a cron jobcloudcloud
4reasoning-heavyStep by step, explain why, analyze, compare, plan, or longer than 400 characterscloudcloud
5simple-taskUp to 200 characters and nothing abovelocalcloud local-unavailable
6default-cloudAnything elsecloudcloud

Held reply

“The local model is off and can’t be reached right now, so this private request was held and not sent to any model. Please try again when it’s back.” Logged as target held, model none, ok false. Nothing is queued for later.

Simulated rate limit

A config flag, router.simulateRateLimit, toggled with a documented command. While on, rules 3 to 6 go to Gemma if it is reachable (reason cloud-rate-limited); otherwise the agent replies that the cloud is unavailable. Turning it off restores normal routing. No real quota is spent.

Timeouts and retries

  • Gemma calls: 120 s timeout to allow a cold load (about 45 s on first use). One retry only if the health poller still reports up.
  • ChatGPT calls: OpenClaw’s own timeout; one retry on network errors, none on 4xx such as an unsupported model.
  • No silent cross-route fallback: if Gemma fails mid-turn, the reply says so and the log shows ok false.

Privacy statement for the README

Private requests are processed only by Gemma on the laptop, or held. The cloud container still orchestrates the turn, stores the conversation in its state snapshot, and logs routing metadata without message text. The README will say this plainly rather than claim data never leaves the laptop.

Key flows

Ordinary message (“What is 12 times 9?”)

  1. Message arrives in the dashboard or Telegram; OpenClaw starts a turn.
  2. Router: no privacy word, no tool word, short, local up, so simple-task to gemma4-a3:e4b. Decision line logged with a request ID.
  3. OpenClaw calls the forwarder, which reaches the laptop through SOCKS5 and Tailscale. Forwarder logs the completed call.
  4. Reply “108” is delivered; the after-turn hook logs the result line with the model that actually answered.

Scheduled morning briefing

  1. Cron fires at 7:30 AM PST in an isolated session.
  2. Router: cron turn, so tool-task to the cloud. (F5 confirms the hook fires for cron; otherwise the job pins the cloud model and logs its own line.)
  3. Agent reads today’s events, runs focus-finder for gaps, gets weather, summarizes top unread email.
  4. Briefing is posted to Telegram; a delivery line records the job ID and date so a restart does not repeat it.

Email draft that needs approval

  1. You ask: “Reply to the test vendor that Thursday works.” Router: tool-task, cloud.
  2. Agent drafts the reply and shows it.
  3. To send, the agent runs send-email. The wrapper checks the recipient against the allowlist; a miss is refused and logged.
  4. OpenClaw shows “Exec approval needed”. Only a human click sends it. In a cron turn nobody can click, so the request times out and only a draft remains, with a Telegram notice.

Local inference fails and recovers

  1. You quit Ollama. Within about 20 s the poller logs local=down.
  2. “This is confidential: remind me my locker code…” matches privacy-sensitive with local down, so it is held: held reply, log target held, ok false.
  3. A non-private question still goes to the cloud (local-unavailable or the normal cloud rule).
  4. You start Ollama. Within about 10 s the poller logs local=up; the next private message goes to Gemma.

Restart and state restoration

  1. Cloud Run restarts the instance (crash, maintenance, or the planned test).
  2. Startup script restores the newest bucket snapshot before the gateway starts and logs state-restored with the snapshot time.
  3. Tailscale comes back with the same machine name from bucket state; the grader link still works.
  4. Missed-job check: if today’s briefing was not delivered and it is before noon, run it once.
  5. Fresh conversation: “What’s my favourite meeting time?” recalls the synthetic preference saved before the restart.

State and concurrency

DataLive locationDurability
OpenClaw config, sessions, cron jobs, workspace files (SOUL.md, USER.md, IDENTITY.md, memory)Container local diskSnapshot every 5 min to gs://…/snapshots/; newest plus previous kept
ChatGPT login (auth profiles)Container local diskCopied to the bucket immediately on every change, because the refresh token is single-use
Tailscale stateBucket mountWritten directly, as the course guide specifies
Alert and job delivery recordsSmall JSON file in stateIncluded in snapshots; keyed by event ID or job and date
  • Single instance and single writer: the snapshot agent is the only process writing snapshots. Uploads go to a temporary object, then replace the newest only if the upload succeeded.
  • Any SQLite file is copied with SQLite’s backup command, not a raw file copy.
  • Delivery-record updates use write-to-temp-then-rename so a crash never leaves half a file.
  • Acceptable loss: up to 5 minutes of chat history. Logins and delivery records are not lost.

Validation and measurement

Performance report

  • Task types: simple, reasoning, private (local only), and tool tasks (cloud only), five fixed prompts each.
  • Run each simple and private prompt cold and warm on Gemma, and the simple and reasoning prompts on ChatGPT for comparison.
  • Latency from route_result and ollama_call lines; quality scored 1 to 3 against a written expected answer; record context size, thinking setting, hardware, and failures.
  • Cost: ChatGPT Edu has no per-request charge; record request counts, plus Cloud Run and storage cost from billing. Gemma cost is local electricity, noted qualitatively.
  • Report only measured numbers.

Functional checks

  • Four video prompts route local, cloud, held, local.
  • Rate-limit flag on and off, with logs.
  • Approval required for a send; non-allowlisted recipient refused; cron produces a draft only.
  • Restart: same Tailscale name, state restored, preference recalled, ChatGPT still logged in.
  • Grader link works from a fresh browser with the laptop off; a non-private question is answered by the cloud.

Evidence collection

  • Keep an evidence/ folder: dated log exports, screenshots, transcripts, and the isolation report.
  • Write PROCESS_LOG.md notes daily: tools and models used, material prompts, AI-generated code attribution, how each piece was verified. The 200 to 300 word narrative and the learning reflection must be in your own words.
  • During the 48-hour run, export logs every 12 hours so an outage cannot erase evidence.
  • Attribute any adapted external code in comments and the process log.
